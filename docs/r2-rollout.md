# デモ文書のR2反映手順

この手順は、Issue #3の公開反映工程で使います。

R2への書き込み、旧オブジェクトの削除、Cloudflareへのデプロイは、人間の明示的な承認を得てから実行します。

## 1. ローカル成果物の確認

文書本文から3冊のPDFを再生成します。

```bash
python3 scripts/generate-demo-pdfs.py
```

各PDFが5ページであることを確認します。

```bash
pdfinfo "output/pdf/経費精算及び出張旅費規程.pdf"
pdfinfo "output/pdf/備品購入及び貸与品管理ガイド.pdf"
pdfinfo "output/pdf/勤怠及び休暇申請ガイド.pdf"
```

## 2. R2用オブジェクトのステージング

次のコマンドはローカルファイルだけを作成し、R2を変更しません。

```bash
python3 scripts/stage-demo-r2.py
```

`.r2-staging/manifest.json`には、18オブジェクトのキー、サイズ、SHA-256を記録します。

内訳は、原本3オブジェクトとページ単位15オブジェクトです。

## 3. 公開環境のバックアップ

書き込み前に、現在の`documents/`一覧を保存します。

旧3冊の原本とページ単位オブジェクトを、回復用ディレクトリへダウンロードします。

バックアップのオブジェクト数とSHA-256を記録します。

秘密情報はログやGitへ保存しません。

## 4. 新しい文書の追加

新しいキーは次の3系列です。

```text
documents/demo-expense
documents/demo-assets
documents/demo-attendance
```

各系列の`pages/1`から`pages/5`も`application/pdf`として追加します。

この時点では旧キーを削除しません。

追加後に、R2上の18オブジェクトを一覧とサイズで照合します。

## 5. アプリのデプロイと確認

最終head SHA、対象アカウント、Worker名、R2バインディングを確認してからデプロイします。

公開URLで次の項目を確認します。

- 新しい3冊が一覧へ表示される
- 各冊の5ページを閲覧できる
- 代表質問の回答と参照ページが一致する
- 幅390pxでChat、管理画面、PDF閲覧を操作できる
- 旧データが画面と回答へ現れない

この確認が成功するまで旧キーを残します。

## 6. 旧オブジェクトの削除

削除対象は、バックアップ一覧と照合して完全なキーを確定します。

人間が削除対象と回復手段を承認した後にだけ削除します。

削除後は、一覧、PDF、代表質問、回答不能質問をもう一度確認します。

## 7. 受け入れ記録

公開反映前のProduct Acceptanceは`NOT_RUN`です。

公開確認後は、LOW、MEDIUM、HIGHの証拠、PlanとRealityの差分、受け入れ結果、人間の確認を記録します。
