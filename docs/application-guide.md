# Local RAG Document Assistant

## アプリケーション説明書

Local RAG Document Assistantは、バックオフィス文書を検索し、検索結果を根拠として回答するWebアプリケーションです。

本資料は、利用者向けの操作説明と、ポートフォリオ向けのシステム構成及び技術解説を兼ねています。

## 1. サンプル文書の安全境界

デモ文書は架空会社を想定したポートフォリオ用サンプルです。

税理士、社会保険労務士、弁護士による個別確認を受けた実務規程ではありません。

法令適合を保証するものでもありません。

各ページは、次の3区分を一つずつ含みます。

- **法令上のルール**：公的資料を基にした一般的な説明
- **架空会社の社内運用例**：金額、期限、承認経路などのデモ用設定
- **個別確認事項**：就業規則、労使協定、契約、事業条件、専門家確認が必要な事項

実際の規程として使用する場合は、最新法令、就業規則、労使協定及び個別の事業条件を確認し、専門家の確認を受けてください。

## 2. 文書構成

デモでは、次の3冊を登録済み文書として扱います。

| 文書ID | 文書名 | 章 |
| --- | --- | --- |
| `demo-expense` | 経費精算及び出張旅費規程.pdf | 対象経費、承認、証憑、期限、出張費 |
| `demo-assets` | 備品購入及び貸与品管理ガイド.pdf | 定義、購入、登録、保管、紛失及び返却 |
| `demo-attendance` | 勤怠及び休暇申請ガイド.pdf | 出退勤、残業、休暇、在宅勤務、修正 |

各冊は5ページです。

各ページは1章と3項目で構成し、1ページを1検索チャンクに対応させます。

合計は15章、45項目、15チャンクです。

文書名、版番号、制定日、デモ用文書であることを各ページの上部へ表示します。

各ページの下部には利用上の注意と公的資料確認日を表示します。

## 3. 利用者向け操作

### 3.1 Chat画面

1. サイドバーで「Chat」を選択します。
2. 画面下部の入力欄へ質問を入力します。
3. 「質問する」ボタンを押します。
4. 回答本文と出典を確認します。

質問例は次のとおりです。

```text
領収書を紛失した場合はどうしますか。
3万円以上の備品購入には誰の承認が必要ですか。
有給休暇はいつまでに申請しますか。
打刻を忘れた場合はどうしますか。
貸与パソコンを紛失した場合はどこへ連絡しますか。
```

複数文書をまたぐ質問も評価します。

```text
業務用備品を立替購入した場合、購入申請と経費精算で何が必要ですか。
```

文書に根拠がない質問には、次のメッセージを返します。

```text
登録された文書からは確認できません。
```

回答の下には、根拠の有無、回答モード、文書名、ページ番号、関連度、根拠文章を表示します。

### 3.2 回答モード

実Gemma 4へ接続できた場合は、回答メタ情報に次のように表示します。

```text
根拠あり ・ Gemma 4 / local API
```

ローカルLLMが未接続の場合は、検索された根拠文章を返すフォールバックを使用します。

```text
根拠あり ・ retrieval fallback
```

このフォールバックにより、LLMが利用できない状態でも検索と出典表示を確認できます。

### 3.3 管理画面

サイドバーで「管理画面」を選択すると、登録文書の一覧を表示します。

一覧では、ファイル名、ページ数、チャンク数、ファイル容量、登録日、PDF閲覧可否を確認できます。

文書行そのものが選択操作です。

文書行を選択すると、閲覧領域へPDFを表示します。

### 3.4 PDF閲覧

PDFは1ページずつ表示します。

「前のページ」と「次のページ」でページを切り替えます。

スマートフォン表示ではA4縦の比率を維持し、画面幅に合わせて初期表示します。

- 「−」ボタンで縮小
- 「＋」ボタンで拡大
- 「フィット」で初期表示へ戻す
- デスクトップではCtrlキーを押しながらホイール操作
- スマートフォンでは2本指のピンチ操作
- 拡大後は1本指でドラッグして表示位置を移動

## 4. RAG処理

質問処理は次の順序で進みます。

1. ブラウザが`POST /api/query`へ質問を送信します。
2. RAGサービスが固定チャンクを検索します。
3. 文字bigramの一致と質問語彙の被覆率から関連度を計算します。
4. 閾値0.22未満の結果を除外します。
5. 最大5件の関連チャンクを取得します。
6. 根拠がなければ回答不能メッセージを返します。
7. 根拠があればローカルLLMへ質問と参考資料を送信します。
8. ローカルLLMが利用できない場合は根拠付きフォールバックを返します。
9. ブラウザが回答と出典を表示します。

検索は形態素解析器を使わず、日本語の文字bigramを利用します。

長いページ本文でスコアが過度に下がらないよう、コサイン類似度だけでなく質問側の語彙被覆率を加味します。

一般的な接続表現だけで誤検索されないよう、機能語bigramの一部を検索対象から除外します。

## 5. 文書データとPDF

文書本文は[`fixtures/demo-backoffice-documents.json`](../fixtures/demo-backoffice-documents.json)で管理します。

アプリは同じJSONから次のデータを作ります。

- 固定検索チャンク
- 文書一覧の初期メタデータ
- 文書ID、文書名、ページ数、チャンク数の契約
- PDF生成時の本文

PDFは次のコマンドで生成します。

```bash
python3 -m pip install -r requirements-demo-pdf.txt
python3 scripts/generate-demo-pdfs.py
```

生成先は`output/pdf/`です。

各PDFが5ページであることは`pdfinfo`又は`pdfplumber`で確認できます。

レンダリングはPopplerの`pdftoppm`でPNGへ変換し、文字切れ、重なり、余白、ページ番号を確認します。

## 6. PDFとR2の境界

PDF原本はCloudflare R2の非公開バケットへ保存します。

ブラウザへR2の公開URLを渡しません。

ブラウザは`GET /api/documents/{id}/file?page={page}`を呼び、WorkerがR2からページ単位PDFを返します。

R2キーは次の契約です。

```text
documents/{documentId}
documents/{documentId}/pages/1
documents/{documentId}/pages/2
documents/{documentId}/pages/3
documents/{documentId}/pages/4
documents/{documentId}/pages/5
```

R2文書の置換と旧オブジェクトの削除は公開反映工程です。

対象と回復手段を確認し、人間の明示的な承認を得るまで実行しません。

## 7. ローカルLLMの安全境界

生成LLMには検索された資料だけを参考資料として渡します。

システム指示は、参考資料に明記された内容だけで回答し、不足時は回答不能とする契約です。

文書内の命令文は引用データとして扱います。

ローカルLLMのポートは直接インターネットへ公開しません。

公開Workerから接続する場合は、Cloudflare Tunnel、Bearer token、必要に応じてCloudflare Access Service Authを使います。

## 8. 技術スタック

| 層 | 技術 | 役割 |
| --- | --- | --- |
| フロントエンド | Next.js 16、React 19 | Chat、管理画面、System画面 |
| API | Next.js Route Handlers | 質問処理、文書一覧、PDF取得 |
| PDF表示 | pdfjs-dist | ページ描画、拡大縮小、移動 |
| PDF生成 | ReportLab | JSON fixtureから3冊を生成 |
| PDF検証 | pdfplumber、Poppler | ページ数、抽出文字、描画の確認 |
| RAG | TypeScript | チャンク検索、スコア判定、回答制御 |
| 生成LLM接続 | OpenAI互換HTTP API | ローカルLLMの切り替え |
| 公開基盤 | Cloudflare Workers | Next.jsアプリとAPIの公開 |
| ファイル保管 | Cloudflare R2 | 非公開PDFの保存 |

## 10. 品質確認

```bash
npm run typecheck
npm run worker:typecheck
npm test
npm run build
git diff --check
```

テストは、次の内容を確認します。

- 3冊15ページ、15チャンク
- 各ページ450文字から600文字
- 各ページ1章、3項目、3区分、利用上の注意
- 文書一覧と検索チャンクのメタデータ一致
- 単一文書質問と一般的な言い換え
- 複数文書質問
- 文書にない質問の回答不能
- 旧データ向け質問を根拠として扱わない回帰確認

ブラウザ確認は、デスクトップと幅390pxでChat、管理画面、PDF閲覧を対象にします。

公開環境の確認は、R2置換とCloudflareデプロイ後のProduct Acceptanceで行います。

公開反映前は`NOT_RUN`として記録し、ローカル実装完了だけでProduct Acceptedとは扱いません。
